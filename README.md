## Hi, I'm Hazel Xue

I build LLM agents and the machinery that makes them trustworthy: post-training loops, data synthesis, evaluation gates, and the sandboxing that lets an agent run code safely. MS student, open to **ML Engineer / AI Engineer internships** working on LLM agents, post-training, or evaluation.

**What I have shipped**

- **Agent post-training.** Designed and landed a bounded self-evolution loop for an SFT → DPO → GRPO ReAct tool-use agent: diagnose weak task families from eval traces, mine bad cases, synthesize targeted training data from train-only parents, freeze every round behind SHA256 manifests, and accept the new policy only if a no-regression gate passes on frozen held-out splits. Agreed with the maintainer before writing code; merged. Then ran one real round on a free T4 (Qwen2.5-0.5B): the targeted data was 100% new rows, nothing regressed, and the gate accepted with ood pass³ 50% → 75%, reported with its small-sample caveats.
- **Verified generation.** Built a Claude Code skill where the model emits a typed spec instead of final output, every factual claim is an executable check against the data, and a gate blocks compilation on failure. Ran an ablation with real model calls: measuring first raised first-draft acceptance from 0% to 100% and halved cost.
- **Agent-framework reliability.** Found and fixed release-day, Windows and dependency-floor bugs in Transformers, nanobot, Haystack, tiktoken, LlamaIndex and DSPy by running their suites where their CI does not (Windows, newest dependencies, and the oldest versions each project declares it supports), bisecting to the exact dependency or torch version, and shipping a regression test with each fix. The Transformers 5.20.0 report was confirmed by a core maintainer within 19 minutes of filing.

### Projects

- [storymap-gen](https://github.com/hazelxue/storymap-gen) · a Claude Code skill plus Python pipeline that turns a topic and GIS data into an ArcGIS StoryMap. The model only emits a typed spec (pydantic); every claim about the data is an executable check against the layer (street-vs-grid bearing, layer statistics), and a quality gate refuses to compile a story with a failing claim. Ablation with real model calls: handing the writer measured facts before drafting raised claim accuracy from 80% to 100% and first-draft acceptance from 0% to 100%, and halved cost per story. 484 tests (unit, property-based, fuzz, MCP protocol, security regressions, offline end-to-end); all three layouts load in the live StoryMaps Builder.
- [fda-predicate-spike](https://github.com/hazelxue/fda-predicate-spike) · can a predicate-retrieval benchmark be built from public FDA 510(k) data, with the predicate a device actually cited as ground truth? One evening, 176K clearances: in a random sample of 400 recent summaries, 93% yield a cited predicate by regex and 99% of those K numbers resolve to a record; a metadata-only TF-IDF baseline with a temporal cutoff puts a cited predicate in the top 10 for 66% of queries, and a product-code filter keeps 95% of the truth while shrinking the pool from 167K to about 190. Write-up lists the benchmark decisions that come first (predicate vs. reference device, multi-predicate metric, self-predicate shortcut, split by year).
